# G3 基准记录：2026-09-23

## 运行条件

- 参数：100 客户端、每客户端 10 条/秒、60 秒、文本消息约 256 字节。
- 目标消息数：60,000 条/次。
- 端点：`ws://localhost:8080/ws/load`。
- Java：OpenJDK 25.0.2。
- Spring Boot：4.1.1；Tomcat：11.0.24。
- Maven：3.9.16。
- 主机：macOS 26.5.1，Apple Silicon，aarch64。
- 应用进程 JVM 参数：`-XX:TieredStopAtLevel=1`。
- 服务端资源：通过 macOS `ps` 每秒采样 Spring Boot 进程的 `%CPU` 和 RSS；RSS 单位为 KiB。
- 延迟定义：负载客户端从 `sendText` 提交到收到服务端回显的端到端 RTT，不是服务端处理时间。

## 解释与限制

- 三次均没有连接、发送、回显匹配或协议错误；前两次精确完成目标消息数。
- 第三次少 100 条，是每个客户端在 60 秒边界少执行一个 100 ms 调度周期导致的计数边界，不应解释为丢包。若要把“精确发送数量”作为验收条件，应让发生器按消息总数收敛，再等待所有 pending 回显后结束。
- 三次 p95 均为 9~10 ms，低于学习基线 200 ms；该基线不是生产 SLO。
- Run 1 的 `%CPU` 峰值超过 100% 是 macOS 进程级多核占用的瞬时采样，不等于单核 142.9% 的错误数据；应结合平均值、采样窗口和机器负载解释。
- 这是单机回显基准，未覆盖 TLS、反向代理、认证、房间广播、持久化、Broker 或多实例路由，不能推出生产容量。
