Lesson 0009 · STOMP

在 WebSocket 上增加消息语义

本课的唯一目标：理解 STOMP 如何把 WebSocket 的消息帧提升为连接、订阅、目的地、确认和心跳语义，并跑通 Spring Simple Broker。

示例项目：examples/0009-stomp-websocket。客户端故意不使用 stomp.js，直接用浏览器 WebSocket API 编码 STOMP 帧。

1. STOMP 与 WebSocket 的关系

WebSocket 规定连接和帧；STOMP 是承载在 WebSocket 消息中的文本协议，规定命令、Header、Body 和订阅目的地。STOMP 不是 WebSocket 的替代品，而是应用层子协议。

层次示例解决的问题
WebSocket101、Text frame、Close如何建立双向长连接并传输消息。
STOMPCONNECT、SUBSCRIBE、SEND消息发给谁、订阅什么、是否确认。
Spring Broker/app、/topic把 STOMP 目的地映射到应用方法或消息代理。

2. 一次消息的完整路径

浏览器 WebSocket /ws-stomp
    ↓  STOMP CONNECT
Spring STOMP endpoint
    ↓
CONNECT → CONNECTED
SUBSCRIBE /topic/room
SEND /app/chat.send
    ↓
ChatMessageController.send
    ↓ @SendTo
Simple Broker → MESSAGE /topic/room

客户端发送到 /app/chat.send，由 ChatMessageController 处理；返回值被发布到 /topic/room，再由订阅该目的地的客户端收到。

3. 源码导读：配置决定路由边界

StompWebSocketConfig 中有三个关键配置：

  • addEndpoint("/ws-stomp") 是 WebSocket 握手入口，不是消息目的地。
  • setApplicationDestinationPrefixes("/app") 表示带有 /app 前缀的消息先进入 Spring 应用方法。
  • enableSimpleBroker("/topic") 表示 /topic 由进程内存中的 Simple Broker 管理订阅和广播。

浏览器客户端中的 frame 函数把 STOMP 命令、Header、Body 和 NUL 结束符拼成一条 WebSocket 文本消息。它让你直接看到 STOMP 与 WebSocket 的嵌套关系。

4. 常见 STOMP 帧

命令方向作用
CONNECT / CONNECTED客户端 ↔ 服务端协商 STOMP 版本、心跳并确认会话。
SUBSCRIBE客户端 → 服务端订阅 destination，得到 subscription id。
SEND客户端 → 服务端向应用或代理 destination 发送消息。
MESSAGE服务端 → 客户端向订阅者投递消息。
ACK / NACK客户端 → 服务端在客户端确认模式下确认或拒绝消息。
DISCONNECT客户端 → 服务端关闭 STOMP 会话。

示例使用 ack:auto 让消息路径保持最小。把 ACK 模式改为 client-individual 并不能自动获得业务可靠投递；仍要设计重复、断线、持久化和重试语义。

5. Simple Broker 与 Broker Relay

Simple Broker 适合学习和单实例场景：订阅状态在当前 JVM 内存中。多实例部署时，每个实例只知道自己的订阅者，通常需要外部 STOMP Broker，通过 broker relay 把消息路由到其他节点。

方案适合场景限制
裸 WebSocket协议和消息模型完全由业务控制。需要自己设计订阅、目的地、错误和确认。
STOMP + Simple Broker单实例或教学、低复杂度应用。订阅和路由不跨实例持久化。
STOMP + Broker Relay需要共享订阅和跨实例路由。引入 Broker 运维、连接和故障语义。
SockJS需要为旧环境提供传输 fallback。增加传输层复杂度；现代浏览器优先原生 WebSocket。

6. 运行和验证

cd examples/0009-stomp-websocket
mvn test
mvn spring-boot:run

打开两个浏览器标签页，都点击 Connect 和 Subscribe，再在一个标签页点击 Send。两个标签页都应收到 MESSAGE。在 DevTools Network 的 WS Messages 中，可以看到 STOMP 文本帧。

7. 练习：先回忆，再验证

运行示例后回答下面 4 个问题：

  1. 为什么 /ws-stomp 和 /topic/room 不是同一种地址？
    查看答案

    /ws-stomp 是 WebSocket 握手入口；/topic/room 是 STOMP 消息目的地，由 Broker 管理订阅和投递。

  2. /app/chat.send 为什么会进入 Controller？
    查看答案

    配置的应用目的地前缀是 /app，Spring 将该消息路由到匹配 @MessageMapping("/chat.send") 的方法。

  3. Simple Broker 为什么不能自动解决多实例订阅？
    查看答案

    它把订阅和连接状态保存在单个 JVM 内存中，其他实例看不到这些订阅，需要外部 Broker 或共享路由。

  4. 使用 STOMP ACK 是否等于消息已经持久化？
    查看答案

    不等于。ACK 只表达客户端对某条 STOMP 消息的确认；是否持久化、如何重试和如何处理重复仍由系统设计决定。
