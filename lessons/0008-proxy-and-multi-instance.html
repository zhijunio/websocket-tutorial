Lesson 0008 · Scaling

连接在哪个节点，消息到哪个节点

本课的唯一目标：通过 Nginx 和两个 Spring Boot 实例复现 WebSocket Upgrade 转发，并解释多实例下本地连接表为什么不够。

示例项目：examples/0008-proxy-and-multi-instance。它包含两个应用容器、Nginx、WebSocket endpoint、HTTP 发布接口和 Actuator 指标入口。

1. 代理必须正确转发 Upgrade

WebSocket 先是 HTTP Upgrade。代理若使用 HTTP/1.0、丢弃 Upgrade/Connection 头，或没有把路径转发到正确服务端，客户端就只能看到普通 HTTP 错误。

location /ws/ {
    proxy_pass http://websocket_nodes;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "Upgrade";
    proxy_read_timeout 60s;
}

proxy_read_timeout 只决定代理多久没有读到上游数据后关闭连接，不是应用心跳。生产中应让心跳周期小于代理 idle timeout，并明确谁负责检测和关闭。

2. 源码和部署路径导读

浏览器 ws://localhost:8080/ws/notifications?alice
        ↓
Nginx :8080
        ├─ Upgrade + HTTP/1.1 + timeout
        ↓
app-a 或 app-b
        ├─ WebSocketConfig → Handler
        └─ ConnectionRegistry（只在本进程内存）

POST /api/users/alice/notifications
        ↓
某一个实例的 NotificationController
        ↓
只查询该实例的 ConnectionRegistry

ConnectionRegistry 是本地连接目录，不是全局用户目录。Controller 返回 deliveredLocally，故意把跨实例投递失败暴露出来。

Nginx 配置只解决连接转发，不解决消息路由。Compose只启动两个独立进程，不会自动共享 Java 堆内存。

3. 多实例路由的选择

方案能解决什么代价或限制
Sticky Session尽量让同一客户端回到同一节点。发布请求仍可能到错误节点；节点故障会丢连接。
共享消息总线任一节点发布，所有节点都能消费并投递本地连接。需要处理重复、顺序、背压和故障。
连接目录 + 定向路由知道用户连接在哪个节点，直接把消息路由过去。需要处理注册过期、竞态和节点故障。
专用 WebSocket Gateway集中持有连接，后端只发布业务事件。网关成为关键基础设施，需要容量规划。

4. 运行和验证

cd examples/0008-proxy-and-multi-instance
mvn test
docker compose up --build
  1. 多次执行 curl http://localhost:8080/api/instance，观察请求可能由不同实例处理。
  2. 通过代理建立 ws://localhost:8080/ws/notifications?alice。
  3. POST 通知，查看返回的 instance 和 deliveredLocally。
  4. 在 DevTools 中确认代理后的握手返回 101。

5. 失败案例

现象根因方向
代理返回 400/404/200检查 HTTP/1.1、Upgrade、Connection、Host、路径和 upstream。
连接空闲后消失比较应用心跳周期和 Nginx/网关 idle timeout。
HTTP 发布成功但 WebSocket 没收到发布请求到达了不持有该连接的实例。
节点重启后用户消失连接是短暂状态，依赖客户端重连和服务端重新注册。

6. 练习：先回忆，再验证

运行 Compose 示例后回答下面 4 个问题：

  1. 为什么 Nginx 正确转发 Upgrade 仍然不能解决多实例消息投递？
    查看答案

    Upgrade 只负责建立连接并选择一个后端节点；session 仍在那个进程的内存里，另一个实例无法直接访问它。

  2. Sticky Session 能否保证发布请求一定到达持有连接的节点？
    查看答案

    不能。发布请求可能来自另一个客户端、任务或服务，仍可能到达不同节点。

  3. 为什么应用心跳周期要小于代理 idle timeout？
    查看答案

    没有上游数据时代理可能先关闭连接；心跳让代理持续观察到流量，但仍需留出抖动和处理时间。

  4. 多实例消息总线至少要考虑哪些语义？
    查看答案

    至少考虑重复、顺序、投递失败、节点离线、连接注册过期、背压和幂等。
