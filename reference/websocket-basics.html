Reference · WebSocket

连接模型与 Opening Handshake

一句话

WebSocket 是先通过一次 HTTP Upgrade 建立连接，再在同一条 TCP 连接上进行双向消息通信的协议。

HTTP 与 WebSocket

维度 反复 HTTP WebSocket
连接 请求通常完成后结束 握手后保持长连接
方向 通常由客户端发起 双方都可主动发送
实时性 轮询或长轮询带来额外延迟/请求 服务端可直接推送
代价 重复 HTTP 头与调度 连接、心跳、扩展和扩容管理

握手骨架

GET /chat HTTP/1.1
Host: example.com
Upgrade: websocket
Connection: Upgrade
Sec-WebSocket-Key: <随机值>
Sec-WebSocket-Version: 13

HTTP/1.1 101 Switching Protocols
Upgrade: websocket
Connection: Upgrade
Sec-WebSocket-Accept: <服务端计算值>

101 表示协议切换成功。Sec-WebSocket-Key / Accept 是握手校验字段，不是业务鉴权；鉴权仍需由 Cookie、Authorization、查询参数或应用层逻辑承担。

排错顺序

  1. 请求是否到达正确的 Host、Path 和网关？
  2. 响应是否为 101，且 Upgrade/Connection 等字段正确？
  3. 失败发生在握手前，还是连接建立后的消息/心跳阶段？
  4. 断线时查看 close code、服务端日志、代理超时和 Origin。
